# LINE Heatmap

`LINE Heatmap` 是一個可直接部署為靜態網站的 LINE 對話分析工具。使用者把 LINE 匯出的單一聊天文字檔 `*.txt` 拖進頁面後，瀏覽器就會在本機完成解析、統計與視覺化，不需要後端，也不會把聊天資料上傳到伺服器。

目前專案由單頁前端組成，適合部署到 GitHub Pages 或任何靜態檔案主機。

## 專案現況

- 純前端靜態網站，沒有 build step
- 使用 `Web Worker` 在背景解析聊天文字檔
- 支援拖曳或手動選取 LINE 匯出的 `.txt`
- 內建匿名化 `demo.txt` 可快速預覽
- 適合分析長時間跨度、訊息量大的單一對話

## 目前提供的分析內容

- 摘要卡片
  - 總訊息數
  - 對話時間跨度
  - 活躍密度
  - 發話平衡
  - 即時回覆節奏
  - 重啟對話間隔
- 圖表與列表
  - 關係洞察
    - 活躍時段
    - 爆量程度
    - 對話黏著度
    - 重啟頻率
    - 回覆不對稱
  - 每週時段熱區
  - 回覆速度分布
  - 月度訊息趨勢
  - 日度訊息趨勢
  - 熱門活躍日期
  - 每位參與者的訊息樣態比例
  - 每位參與者的愛用詞彙與口頭禪候選
  - 參與者比較
  - 常見語詞線索
  - 可辨識的互動線索與通話欄位（若匯出內容有提供）

## 支援的資料來源

目前以 LINE 匯出的單一聊天文字檔為主要目標，格式會長得像：

```text
2025.12.24 星期三
22:33 Alex 貼圖
22:34 Blair 你到了嗎
```

解析器會根據日期行、時間、發話者名稱與訊息內容還原出聊天節奏，並把 `貼圖`、`圖片`、`影片` 這類佔位文字視為訊息型態。

## 隱私

- 所有處理都在本機瀏覽器內完成
- 專案本身沒有後端，也不會主動上傳聊天資料
- 不建議把私人匯出檔提交到 Git repository

## 專案結構

- `index.html`: 頁面結構、上傳區與各分析面板
- `styles.css`: 版面與視覺樣式
- `app.js`: UI 邏輯、圖表渲染、互動控制
- `worker.js`: LINE 文字匯出解析與聚合統計
- `demo.txt`: 匿名化示範聊天資料

## 本機預覽

因為頁面使用 `type="module"` 與 `Web Worker`，不要直接雙擊 `index.html` 開啟，請用靜態伺服器預覽。

例如：

```bash
python3 -m http.server 4173
```

然後開啟：

```text
http://localhost:4173
```

## 部署

此專案沒有打包流程，直接把以下檔案部署成靜態網站即可：

- `index.html`
- `styles.css`
- `app.js`
- `worker.js`
- `demo.txt`

## 實作說明

- 解析器會先讀出日期行，再把 `HH:MM 發話者 訊息內容` 格式整理成可分析的訊息
- 統計以聚合結果為主，不保留完整訊息清單在記憶體中
- 熱門詞與口頭禪改用精確詞頻統計，中文以候選詞切分與停用詞過濾整理
- 回覆速度以雙方交替發話的時間差估算，不是語意層級的精確回覆鏈
- 首頁摘要與關係洞察優先針對個人對話設計，會強調互動節奏、重啟頻率與雙向回覆差異
- 純文字匯出若沒有反應、編輯、通話等 metadata，相關面板會顯示為空

## 已知限制

- 目前主要針對 LINE 單一聊天的文字匯出，群組聊天的摘要指標仍以個人對話優先設計
- 解析器仰賴日期行與發話者名稱重複出現來辨識訊息；如果匯出格式差異太大，可能無法正確分辨說話者
- 中文詞彙分析不是完整 NLP 斷詞器，而是以前端可部署為前提的候選詞切分；遇到黏在一起的長句仍可能切得不夠理想
- 熱門詞、愛用詞與口頭禪改為精確詞頻統計，但候選詞品質仍受停用詞與切分規則影響
- 回覆速度不會排除長時間沉默，超過 1 天會落在 `>1d`
- LINE 純文字匯出通常不包含 reactions、edits、forwards 與完整通話資料
